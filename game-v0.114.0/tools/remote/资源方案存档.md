# 租用机资源方案存档

每次大改训练结构、需要重新调资源之前，把当时在用的方案和实测表现记在这里，便于对比和回退。
租用机：RTX 3090（24 GB）、Xeon E5-2686 v4（18 核 36 线程）、64 GB 内存。

## 方案一：构筑训练之前（第 8,360–8,637 版，2026-10-25 停用）

完整配置存在租用机 `~/.local/share/sls2/runs/defect/train_config.2026-10-25-构筑训练前.json`。

| 项目 | 取值 |
| --- | --- |
| 采集进程 × 每进程引擎 | 8 × 16 = 128 个引擎 |
| 采集推理 / 学习 | 都在显卡上，开 CUDA MPS |
| 采集进程线程、凑批等待 | 1 线程，2 ms |
| 学习进程线程 | 4 |
| 每批决策数 / 小批 / 遍数 | 32,768 / 4,096 / 2 |
| 评测 | 5 个工作进程，cgroup 限 5 核，连续评测 192 局 |
| 网络 | d=256、4 层 |
| 训练内容 | 整局占 0.3；Boss 名额 0.15；第二幕真实快照 0.15 |

实测（第 8,431–8,630 版，200 次更新平均；机器占用为停用前 2 小时平均）：

| 指标 | 数值 |
| --- | --- |
| 吞吐 | 5,498 决策/秒 |
| 每次更新：学习 / 等数据 | 5.22 秒 / 0.54 秒 |
| 每次更新丢弃的过旧对局 / 过旧步数 | 122 局 / 5,639 步 |
| CPU / 显卡占用 | 66% / 81% |
| 内存 / 显存 | 38 GB / 18 GB |

结论：学习是瓶颈，采集有富余（采集进程大部分时间被队列反压挡住，还会产生过旧的数据）。

同一套资源配置换上构筑训练（整局 0.5、Boss 0.2、第二幕 0.35）之后，前 52 次更新：吞吐 5,366 决策/秒，学习 5.40 秒、等数据 0.53 秒，CPU 72%、显卡 70%。

## 方案二：构筑训练（第 9,068 版起，2026-10-25）

完整配置存在租用机 `~/.local/share/sls2/runs/defect/train_config.2026-10-25-构筑训练.json`。相对方案一的改动：

| 项目 | 方案一 | 方案二 |
| --- | --- | --- |
| 采集进程 × 每进程引擎 | 8 × 16 | 12 × 16 = 192 个引擎 |
| 训练内容 | 整局 0.3、Boss 0.15、第二幕 0.15 | 整局 0.5、Boss 0.2、第二幕 0.35 |
| 代码 | — | 上下文表示不再按整批最长填充；牌组打分并入采集推理的同一次前向 |

其余（采集与学习都在显卡上、MPS、凑批等待 2 ms、每批 32,768 / 小批 4,096 / 2 遍、评测）不变。

调优过程（每项都是重启后跳过前 1.5–3 分钟、取 40–60 次更新的平均）：

| 步骤 | 吞吐（决策/秒） | 学习 / 等数据（秒） | CPU / 显卡 | 说明 |
| --- | --- | --- | --- | --- |
| 方案一的资源 + 构筑训练 | 5,404 | 5.38 / 0.53 | 76% / 81% | 学习是瓶颈；等组批只占 0.16 秒，瓶颈在显卡计算 |
| 凑批等待 2 → 6 ms | 5,341 | 5.43 / 0.51 | 74% / 73% | 无变化：采集推理抢显卡不是主因，改回 2 ms |
| 上下文表示不再按整批最长填充 | 4,576 | 3.14 / 3.95 | 64% / 49% | 学习快了约四成；同期打分头开始给奖励，采集要多跑一次前向，转为采集瓶颈 |
| 打分并入同一次前向 | 5,777 | 3.20 / 2.31 | 73% / 63% | 仍是采集瓶颈 |
| 10 个采集进程 | 约 6,600（稳定后） | 3.3 / 1.4 | 82% / 81% | |
| 12 个采集进程 | 7,058 | 3.63 / 0.79 | 87% / 59% | |
| 13 个采集进程 | 6,969 | 3.62 / 0.84 | 90% / 60% | 不再提升，过旧数据变多，可用内存只剩 11 GB |
| **定为 12 个（复测 60 次更新）** | **7,228** | 3.56 / 0.76 | 87% / 69% | 内存 51 GB，显存 13 GB |

离线测速（一批真实学习数据，32,804 步，训练暂停时独占显卡）：

| 方案 | 学习吞吐（样本/秒） |
| --- | --- |
| 改写前 | 15,580 |
| 改写前、去掉地图节点（只用来估算地图节点占的算力） | 38,135 |
| 改写前、编译注意力层 | 16,633（预热 92 秒） |
| 改写后 | 30,758 |
| 改写后、小批 8,192 | 36,532 |

采集推理（每批 128 步、只前向）：不分组 9.1 ms，分组 15.1 ms，所以小批仍不分组。

现在的瓶颈是 CPU（引擎）。显卡还有余量，但再加采集进程已经没有收益。小批改为 8,192 能让学习再快约两成，但每轮的梯度步数会减半，改变了优化过程，所以没有采用；采集不再是瓶颈之后可以再评估。
