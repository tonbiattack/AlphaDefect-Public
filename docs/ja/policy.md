# 実ゲーム運用の方針とランチャー仕様（#71）

このリポジトリで「実ゲームを AI に操作させる」ときの**方針**と、ランチャーの**実際の挙動**をまとめます。
UI に項目があることと、その設定が実際に効くことは別なので、区別して書きます。

- 記録時点: `main` = ee5b2f0 / ゲーム v0.111.1 / Windows 11 + WSL2 / Spire Mentor（MIT, fork 元と同期）
- 検証は実機（v0.111.1）で行ったものを「確認」、コードから言えるだけのものを「未検証」と書きます。

---

## 1. 方針

| 用途 | 担当 | 位置づけ |
|---|---|---|
| **実ゲームの AI 操作・観戦** | **Spire Mentor（第一選択）** + AlphaDefect のモデル/観測/推論 | 標準 |
| 実ゲームの AI 操作（代替） | 独自 MOD（`AlphaDefectAutopilot`） | **レガシー / 比較検証 / 障害切り分け用**。新機能の二重実装はしない |
| 通常プレイ | ゲーム本体（MOD なし） | そのまま |
| 性能評価・観戦 | ヘッドレス実行 / リプレイビューア（#69） | 別用途として維持（廃止しない） |

- 学習済みモデル・観測エンコーダ・語彙・推論サーバは AlphaDefect 側が持ちます。
- 画面操作・画面遷移・状態同期は Spire Mentor 側に任せます。
- **モデルの判断を独自ルールで上書きしない**のが原則です（例外は `docs/ja/fidelity-audit.md` に理由つきで記録）。

## 2. 推奨の起動方法

### Windows（GUI）

`launcher.cmd` をダブルクリック（デスクトップに「AlphaDefect ランチャー」ショートカットを作成済み）。

1. モード: **Mentor 観戦（spire-mentor）** を選ぶ
2. キャラ（`auto` / `DEFECT` / `REGENT` / `SILENT` / `select`）、アセンション、シード（乱数可）、ラン数を設定
3. 「起動」

### CLI

```bash
./play.sh mentor --character DEFECT --seed 12345 --runs 1      # Mentor 観戦（標準）
./play.sh launch ai --character auto                            # 独自 MOD（レガシー）
./play.sh launch normal                                         # 通常プレイ
```

### 必要なもの

| 項目 | 内容 |
|---|---|
| ゲーム | Slay the Spire 2 v0.111.1（Steam インストール） |
| ゲーム側 MOD | `SpireMentor`（+ BaseLib）と `AlphaDefectAutopilot`（`mentor.txt` があるとき Mentor クライアントとして動く） |
| 推論サーバ | `local autopilot`（Mentor モードでは**ランの開始をせず**推論だけ担当） |
| モデル | `weights/` の目録とハッシュ（`python -m local setup` で取得） |

通常プレイに戻すには、モードで「通常プレイ（MOD なし）」を選ぶか `./play.sh launch normal`。

## 3. ランチャー設定の一覧（モード別）

| 設定 | 通常プレイ | AI 観戦（独自 MOD） | Mentor 観戦 | 備考 |
|---|---|---|---|---|
| キャラ | 無視 | `--character` として渡る | `mentor.json` の `character` になる | `auto` は**その版で動くキャラの先頭**（ランダムではない） |
| アセンション | 無視 | **渡らない**（0 固定） | `mentor.json` の `ascension` | ゲーム側プロファイルが未解放だと A0 になる |
| シード（乱数） | 無視 | `--seed` | `mentor.json` の `seed`（`null` で乱数） | 実際の seed はゲーム側が決める |
| 速度 | 無視 | `--speed`（TimeScale） | **GUI からは渡らない**（起動後に `launch --set-speed` で変更可） | Mentor では速度欄は効かない |
| 行動間隔 | 無視 | `--pacing` | **GUI からは渡らない**（`{"command":"pacing N"}` で変更可） | パネル/HTTP で変更する |
| ラン数 | 無視 | 1 固定 | `--runs` → `SpireMentor.conf` の `num_runs` | GUI は 1〜20 |
| 起動 / 停止 / 状態 | ○ | ○ | ○ | 「停止」は起動したプロセスを止め、サーバにも停止を要求 |
| 一時停止 / 1 手 / 手動 | ○ | ○ | ○（推論サーバ経由） | 手動は「推奨のみ表示」 |

**UI にあるが効かない組み合わせ**（重要）:

- Mentor モードの**速度・行動間隔**は GUI の欄からは反映されません（起動後に HTTP/パネルで変更してください）
- AI 観戦モードの**アセンション**は渡りません（0 固定）

---

## 4. `auto` / `select` / 既存ランへの接続

| モード | 実際の挙動 |
|---|---|
| `auto` | その版で動くキャラ（`versions.py` の validated）のうち、**ゲームが提示する最初のもの**で開始。ランダムではない |
| `select` | **ランを開始しない**（`client_run_config` は有効のまま、`auto_start` を false にする）。ゲーム内で自分で始めても、**Spire Mentor の autopilot はメニューからの開始のみ対応**のため引き継がれない（#65 の領域） |
| 既存ランへの接続 | **未対応**（#65）。Mentor はメニューから新しいランを始める経路のみ |

---

## 5. 複数ラン

- GUI で 1〜20 を選ぶと `--runs N` が渡り、`SpireMentor.conf` の `num_runs` に反映されます
- 推論サーバは `--keep-listening` で待ち続け、Mentor が次のランを始めれば同じサーバで推論します
- **実際に確認したのは 2 ラン**（1 セッションでキャラ変更あり、モデルも切り替わった）。**3 ラン以上は未検証**
- ランの終了は `game_over` を受けて記録し、次の `run_config` で状態をリセットします
- SELECT モードではラン数は使われません（開始しないため）
- 途中停止した場合: 「停止」でプロセスとサーバを止めます。ゲームは残るので、再度「起動」してください

## 6. 制約（実装と環境）

| 制約 | 内容 | 関連 |
|---|---|---|
| アセンション | プロファイルが未解放だと、指定しても A0 で開始（ゲームログに `has not revealed the Ascension Epoch`） | #41 |
| ゲーム版 | v0.111.1 で検証。v0.113.1 / v0.114.0 は別途 | #73 |
| ポーション | **Mentor では有効**、独自 MOD では既定で無効（使用後に選牌が開くポーションで止まる既知問題） | #67 |
| ルール代替 | カード報酬の再表示・複数枚選択の残り・水晶球はルール。回数は `fidelity` 行で確認 | #68 |
| 観測・合法手の差 | 候補ラベルは 100 件で不一致 0 を確認。特徴量レベルの比較は未実施 | #28 |
| 既存ゲームへの接続 | 未対応 | #65 |

## 7. トラブルシューティング

ログの場所:

| 種類 | 場所 |
|---|---|
| ゲーム（MOD のログもここ） | `%APPDATA%\SlayTheSpire2\logs\godot.log` |
| 推論サーバ | `~/.local/share/sls2/logs/mentor-server.log`（GUI 起動時）、または `--log` で指定した JSONL |
| Spire Mentor | 同じ `godot.log` に `[SpireMentor]` で出る |

代表的な症状と確認:

| 症状 | 確認すること |
|---|---|
| 起動してもランが始まらない | `godot.log` に `[mentor] answered run_config` があるか。無ければ `SpireMentor.conf` の `auto_start` と `mentor.txt` の有無。GUI のログ欄に `unrecognized arguments` が出ていないか |
| AI が動かない（画面が止まる） | `[mentor] chosen` が出ているか。出ていれば相手待ち、出ていなければ推論サーバの接続（`connected` の有無）とモデルのロードエラー |
| `card_select reply rejected` が続く | 直前の `card_select: cards=... min=... max=...` と `select multi reply` の枚数 |
| ポーションを使わない | 独自 MOD では既定で無効。Mentor では有効（`用 ...` のログが出るか） |
| 設定が反映されない | Mentor の速度・間隔は GUI から効かない（本ドキュメント 3 章）。アセンションは解放制約 |
| 休憩で休まない | 修正済み（ee5b2f0）。古い MOD が入っていないか `mod install` で確認 |
| モデルが違う | `[mentor] answered run_config` のキャラと、推論サーバの `action` ログのキャラが一致しているか |

安全な復旧手順:

1. GUI の「停止」（または `./play.sh launch --stop`）
2. ゲームを終了
3. `./play.sh mod install` で MOD を入れ直す
4. もう一度「起動」

## 8. 今後の開発での扱い

- 実ゲーム連携の新機能・修正は **Mentor 経由を前提**に検討する（独自 MOD に二重実装しない）
- 独自 MOD 専用の既存 Issue は閉じず、Mentor への影響と必要性を個別に評価する
- ヘッドレス実行・ビューア（#69）は性能評価と観戦の用途で維持する

---

## 9. 改善候補（本 Issue では整理のみ）

- GUI の既定モードを Mentor にする
- Mentor 選択時に効かない設定（速度・間隔・アセンション）をグレーアウトする
- 指定ラン数までサーバを維持し、勝敗後に次ランを自動で始める（3 ラン以上の実測とセットで）
- 進捗・勝敗・勝率を GUI に表示し、指定回数で停止する
- 既存ランへの接続（#65）
