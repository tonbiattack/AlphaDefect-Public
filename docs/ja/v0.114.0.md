### MOD の v0.114.0 対応（このコミット）

- `local/mod.py`: インストール版の系統から観測エンコーダを選ぶ（`-p:ObsTree`）、v0.114.0 では `-p:Sts2V114=true`
- `AlphaDefectAutopilot.csproj`: `Sts2V114=true` のとき `STS2_V114` を定義
- `OutOfCombat.cs`: v0.114.0 の API に合わせた分岐
  - 店の在庫: `RunManager.Instance.MerchantSynchronizer.GetLocalInventory()`
  - 購入: `OnTryPurchaseUnsynchronized(inv)`
  - 報酬画面から進む: `ProceedFromTerminalRewardsScreenAsync()`
- `Launcher.cs`: v0.114.0 では**レガシーの自前ラン開始を無効化**（シグネチャ変更。Mentor 連携では spire-mentor が開始するため不要）

### 追加で分かったこと（同日）

- **SpireMentor を v0.114.0 向けにビルドし直した**（fork `tonbiattack/spire-mentor` の `2b28833` を clone し、
  `dotnet build -p:STS2_GAME_DIR=<game> -p:BaseLibDir=<game>/mods/BaseLib`。ビルドが自動で `mods/SpireMentor/` へ配置）
- **IRONCLAD で実ゲーム Mentor 観戦が成立**（v0.114.0・128 意思決定・floor 9 まで・エラーなし）
- 途中で見つけた不具合: 固定キャラで起動してもサーバを `--character auto` で起動していたため、
  `welcome` に観測形式が載らず、**フレーム 29 と重み 28 の不一致**で推論が止まっていた
  → `_start_mentor` がキャラをサーバへ渡すように修正（auto のときだけ auto）
- **FOOL はこのプロファイルで未解放**。spire-mentor は `requested "FOOL"` に対して
  `CHARACTER.IRONCLAD` を選び、**黙って別キャラで開始**した（ログに `Selecting character: CHARACTER.IRONCLAD (requested "FOOL")`）。
  キャラが違えば観測もモデルも変わるため、これは検出して止めるべき挙動（#72 の課題）

### 残るブロッカー

**SpireMentor を v0.114.0 向けにビルドし直す必要があります**（インストール済みの MOD は v0.111.1 向けにビルドしたもの）。
upstream は v0.114.0 対応を含むため、fork（tonbiattack/spire-mentor）を clone して
`dotnet build -p:STS2_GAME_DIR=<game>` で作り直し、`mods/SpireMentor/` に入れ替えて再試行します。
